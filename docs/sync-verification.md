# 时间码同步与帧偏移校验

两台 X5 要做到"对齐"，需要区分两件不同的事：

| 层面 | 含义 | 工具能做到的 |
|---|---|---|
| **命令派发** | 两台相机被写入"开始录制"命令的时刻差 | ✅ 实测 ≤ 0.05 ms（`multi shell` 每次输出） |
| **画面起点** | 命令到达后，相机内部启动管线、第一帧曝光的时刻差 | ❌ 协议不可观测；需要用素材实测 |

**关键结论**：软件触发只能把"命令派发"做到微秒级；"画面起点"的残差取决于相机内部
延迟（两台可能不同），只能通过**时间码对齐**或**后期实测校正**来解决。

## 1. 为什么时间码能解决对齐问题

X5 原生支持 Timecode：时间码会写入视频文件的 **Timecode Track**，剪辑软件可以按
时间码自动对齐多机位轨道。只要两台相机的**运行时钟一致**，各自何时开始录制就不再
重要——每帧都带着自己的时间码，对齐是逐帧精确的。

官方文档（X4 / X4 Air / X5）：
<https://onlinemanual.insta360.com/x5/en-us/operating_tutorials/step/tc>

### 时钟对齐的三条路径

**路径 1（官方推荐）**：相机菜单 → 设置 → Timecode → "Sync system time"，
分别连接 Insta360 App，在 Timecode 页点右下角刷新。两台都校准后时钟一致
（App 用网络时间校准，误差通常在几十毫秒以内）。

**路径 2（帧级最准，硬件）**：外接音频 LTC 时间码发生器（官方兼容 Tentacle Sync /
Atomos / Easync），经 Mic Adapter 接入相机；两台吃同一路 LTC。

**路径 3（软件脚本）**：`tools/osc_timesync.sh` 通过官方 OSC API 尝试把两台相机的
`_dateTime` 写成本机时间。注意：
- 需要本机临时切到相机热点（脚本会自动恢复原网络）；
- `_dateTime` 是否可写取决于固件，脚本会打印相机返回结果；
- 单机版：`tools/osc_settime.py`。

### 手动依次对时（不连 App）

在 设置 → Date and Time 里把两台改成**同一个未来时刻**（例如都设 16:00:00，
尽量同时按确认）。误差 = 两次操作的间隔（秒级），这会在两台 TC 之间留下一个
**固定偏差 δ**。同一开机周期内 δ 不变——用下面的方法量出 δ，后期统一补偿即可。

## 2. 快速量时钟差（秒级，无需导出素材）

`multi shell` 每次 `stop` 都会打印两台刚录制的文件名：

```
| file: ./DCIM/Camera01/VID_20261009_151104_00_058.insv    ← 15:11:04
| file: ./DCIM/Camera01/VID_20261009_151100_00_029.insv    ← 15:11:00
```

两台同一瞬间开始录制，文件名里的 `HHMMSS` 差就是时钟差（秒级精度）。
实测示例：连续三轮稳定相差 4 秒；手动对时后应变为同一秒。

## 3. 帧级偏移校验（拍手法）

录制时在双机前**拍一次手**（或使用 LED 闪光 + 蜂鸣），导出视频后：

```bash
python3 tools/sync_check.py A.mp4 B.mp4 --fps 30
```

输出示例：

```
event position  A: 0.9990s   B: 1.1362s
offset (B-A): +137.21 ms  =  +4.12 frames @ 30fps
```

- 工具用 ffmpeg 抽取音频，定位两段素材中**第一个强瞬态**（拍手声）的位置差；
- 合成信号验证精度约 ±0.2 ms（≈1 个采样点）；
- **偏移稳定**（大小和符号每次一致）→ 后期对所有成对素材统一校正；
- **偏移漂移** → 每条素材单独测。

> 依赖：numpy + ffmpeg（`pip install imageio-ffmpeg` 可提供自带静态 ffmpeg）。

## 4. 推荐工作流

1. 两台相机：Timecode → "Sync system time"（或手动对时 + 量 δ）；
2. 用 `multi shell` / 网页控制台同步开录；
3. 每组素材录一条"拍手标记"（1 秒即可）；
4. 导出后用 `sync_check.py` 量出真实偏移，后期统一校正；
5. 相机重启 / 重新对时后，δ 可能变化——重新量一次。

## 5. 常见误区

- ❌ "命令同时发出 = 画面同时开始"：派发差 ≤ 0.05 ms，但画面起点差是另一回事
  （相机内部启动延迟，两台可能不同）；
- ❌ "文件名秒数相同 = 对齐了"：文件名只有秒级精度，帧级要靠 TC 或拍手校验；
- ❌ "BLE 协议里有 genlock"：没有；BLE 遥控协议不提供时间码或同步信号，
  时间码是相机本地功能（App 校准或外接 LTC）。
